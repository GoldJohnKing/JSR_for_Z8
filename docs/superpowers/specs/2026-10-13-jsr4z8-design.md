# JSR for Z8 —— 设计文档

日期：2026-10-13
状态：待用户批准

## 1. 背景与意图

Jiangtherapee Bridge 2.3.25 是一套多帧 RAW 超分辨率工具（Python 后端 + WGPU/Vulkan 计算，PyInstaller 打包，闭源）。**已获原作者同意：逆向原始项目作为参考，并将后端原包及其内含数据（含 PTC 表）再分发**。其原 GUI 冗杂、手动参数过多。

本项目为其 Python 后端**重写**一个 GUI 客户端：只服务 Nikon Z8 的七帧 RAW 超分辨率这一条核心链路，界面做到「加完就跑」，输出完整元数据的无损压缩 DNG，最终以**单一 exe** 分发，内嵌原版后端原封不动。

## 2. 目标 / 非目标 / 反目标

**目标**

1. C#/.NET 8 + AvaloniaUI 桌面应用（中文界面），沿用 Save_Z8（`D:\GitRepos\Save_Z8`）的技术栈与工程模式。
2. 原版后端（`Jiangtherapee Bridge.exe` + `resources/`）**不改动、原封不动**打包进新 GUI，首次运行释放后经命令行调用。
3. 前后端以命令行通信，后端 stdout/stderr 实时展示在界面。
4. 仅支持七帧 RAW 后端（engine `stormer7`，mode `full`）。以首张 RAW（文件名升序第 1 张）为基准参考帧；视 7 帧曝光相同。
5. 多任务组队列：每组 = 7 帧 RAW + 黑场文件 + 自动匹配 PTC。8 个文件（7 帧+黑场）机型与 ISO 任一不一致 → 拒绝执行。
6. 黑场必须提供文件，无手填黑场参数入口。
7. PTC 按机型+ISO 自动匹配，本轮仅 Nikon Z8（数据从原项目 `ptc_index.csv` 提取）；匹配不到 → 拒绝执行。
8. 表外 ISO 用双段线性拟合：ISO<500 一条拟合线，ISO≥500 一条拟合线。
9. 输出 DNG 在后端产物基础上补全：EXIF（含曝光/白平衡等）、镜头畸变/暗角/CA 校正 Opcode、内嵌预览图，并启用无损压缩（Compression=7）。移植自 Save_Z8。
10. 高级设置：显存预算（滑块 1–16GB，默认 4）、输出路径（同输入目录/自定义）、临时路径（默认 %TEMP%/自定义），全局生效、持久保存。
11. 输出文件名固定 `JSR_<基准帧文件名>.dng`（如 `JSR_DSC_7576.dng`）。
12. GUI 全新设计（不参考原版），定稿见 §5。
13. 依赖引入按 Save_Z8 先例：原生 C/C++ 库用 git submodule，.NET 库用 NuGet 锁定版本。
14. 一键编译脚本：编译全部依赖 → 单文件 self-contained exe 分发。
15. 开发在 WSL，编译与真实测试在 Windows Host 执行。

**非目标**

- 其它机型（仅 Z8）、其它帧数模式（K14/fastk14）、去鬼影、ROI、包围曝光、TIFF/预览输出、多语言、自动更新、DeepSeek 助手等原版其余功能。
- 修改 Python 后端任何文件；解包/重打包其 Python 源。

**反目标**

- 允许手填黑场参数或手选/手填 PTC（即使后端支持）。
- 后端包内文件被裁剪或替换（包括看似无用的 Tk 运行库——保持逐字节原样）。

## 3. 关键事实（已勘察确认）

- 后端无界面入口（实测可用）：`"Jiangtherapee Bridge.exe" --assistant-jsr-job <request.json> <resources目录> <config目录>`；错误经 stdout `ASSISTANT_JSR_ERROR|<消息>` 返回，exit 1。
- 请求 JSON（原版 DeepSeek 助手 SDK 文档 + 实测）：
  ```json
  {"paths": ["7个绝对路径"],
   "parameters": {"engine":"stormer7","mode":"full","output":"<输出目录>","prefix":"<前缀>",
                  "manual":false,"dark":"<黑场绝对路径>","fullwell":<e-或null>,"ptc":"",
                  "color":"libraw","dng":true,"tiff":false,"preview":false,"deghost":false,
                  "memory":<显存GB>}}
  ```
- 同一 config 目录有排他锁 → 每个运行中任务用独立 config 目录即可规避。
- PTC 数据：`resources/_internal/ptc_index.csv`（DXO SNR 库导出）。Nikon Z8 含 ISO 50/100/200/400/800/1600/3200/6400/12800/25600/51200/102400 共 12 档，字段含 `alpha`（满阱=1/alpha，单位 e⁻）、`beta_total`、`prnu_variance` 等。原版自身语义：精确 ISO 取表值，表外 ISO 在相邻两档间对 FWC（=1/alpha）线性插值。
- 后端运行时规模：exe 14MB + `resources/_internal` 215MB（Python 3.10、numpy、cv2、rawpy、wgpu、weights.npz 3.7MB 等），计算走 Vulkan（WGPU），无 CUDA。
- 样例：`samples/DSC_7575.NEF`（黑场）+ `DSC_7576–7582.NEF`（七帧，同曝光）。
- Save_Z8（本项目作者自己的项目，代码可自由复用）已有的可移植资产：LibRaw fork（submodule `nikon-he-production`，**公开仓库**，可直接 clone）、libjpeg-turbo（submodule）、`DngWriter`（与 Adobe DNG Converter 18.6 逐字节对齐）、`NikonLensCorrection`（NEFInfo→WarpRectilinear/FixVignetteRadial/CA Opcode）、EXIF/GPS/XMP 搬迁、三级预览嵌入、无损 JPEG 压缩（14-bit 原生域 BL=1008/WL=15892）、`build.bat` 单文件发布模式。**移植方式：复刻相关源文件到 `Jsr4Z8.Core`（保留源文件头注与出处说明），Save_Z8 项目本身不作为 git submodule 引入。**

## 4. 架构

### 4.1 进程与数据流

```
用户 ──▶ Avalonia GUI（Jsr4Z8.UI）
            │ 校验/PTC/排队/日志展示
            ▼
        任务执行器（Jsr4Z8.Core）
            │ 生成 request.json，spawn 原版 exe（--assistant-jsr-job）
            │ 独立 config 目录 · stdout 逐行转发（解析进度尽力而为）
            ▼
        原版后端（释放于 %LOCALAPPDATA%\JSR4Z8\backend\<hash>\）
            │ 输出裸 DNG 到任务临时目录
            ▼
        DNG 完整化（移植 Save_Z8 DngWriter）
            │ 基准帧 NEF 元数据 + 后端像素 → 无损压缩完整 DNG
            ▼
        <输出路径>\JSR_<基准帧名>.dng
```

- **单 exe 分发**：self-contained 单文件发布；后端载荷（exe+resources，压缩嵌入）首次运行释放到 `%LOCALAPPDATA%\JSR4Z8\backend\<载荷SHA256前16位>\`，带完整性校验（按原包 `FILES-SHA256.json` 或自行生成的清单）。
- **队列**：顺序执行，一次一组；失败/停止不阻断后续组。
- **临时文件**：任务工作目录 `<临时路径>\Jsr4Z8\<任务ID>\`（含 config 目录、request.json、后端原始输出）；成功后清理，失败保留供诊断。
- **日志**：内存 + 落盘 `%LOCALAPPDATA%\JSR4Z8\logs\<任务ID>.log`。

### 4.2 校验与 PTC

- LibRaw 读取 8 个文件的机型与 ISO：全部 == Nikon Z8 且 ISO 两两一致才放行；不一致的文件在卡片芯片上标红并给出人话错误条（哪个文件、差在哪、建议动作）。
- PTC：提取 CSV 中 Nikon Z8 12 档为程序内嵌资源。ISO 在表内 → 满阱=1/alpha 表值；表外 → 双段最小二乘线性拟合（<500 段用 50/100/200/400 点；≥500 段用 800–102400 点）。
- **拟合出的满阱显式写入请求 `fullwell` 字段** → 界面显示值与后端实际使用值严格一致。
- 拟合实现时用两段表内点做留一交叉验证，并与原版「相邻档插值」语义对照，残差过大时在文档化前提下调整拟合空间（如 log 域），这是构建者的实现细节决策。

### 4.3 DNG 完整化（复刻 Save_Z8 源文件）

移植方式：把 Save_Z8 中 `DngWriter`/`NikonLensCorrection`/`TiffIfdExtractor` 等相关源文件**复刻进 `Jsr4Z8.Core`**（保留原头注、按新命名空间适配），不引入 Save_Z8 为 submodule。后端产出的 DNG 只有像素与基本 CFA 标签。后处理器：

1. 读基准帧 NEF：EXIF/GPS/Interop/XMP、白平衡（cam_mul→AsShotNeutral）、NEFInfo（镜头校正）、三级内嵌 JPEG 预览、ADC 域黑白电平（Z8 压缩域 BL=1008/WL=15892）。
2. 读后端 DNG：CFA 像素与其黑白电平，归一化后重标到 14-bit 压缩域。
3. 按Save_Z8 的 DngWriter 结构写最终 DNG：IFD0（缩略图+基线/色彩+EXIF+SubIFDs）、raw IFD（CFA+OpcodeList2/3：WarpRectilinear/FixVignetteRadial/CA）、预览 IFD、无损 JPEG（libjpeg-turbo，Compression=7）。
4. 落盘 `JSR_<基准帧名>.dng` 到配置的输出路径。

后端 DNG 的具体标签布局与像素域在首次真实运行时实测确认，适配层做归一化（不假设与 NEF 同域）。

### 4.4 工程结构与依赖

```
JSR_for_Z8/
├─ external/
│  ├─ libraw/            submodule: y-g-jiang/LibRaw @ nikon-he-production
│  └─ libjpeg-turbo/     submodule
├─ reference/            原版 2.3.25 包（构建时作为后端载荷来源，不入库分发）
├─ samples/              测试样例
├─ src/
│  ├─ Jsr4Z8.Core/       LibRaw 互操作、校验、PTC、后端执行器、DNG 后处理、载荷管理
│  └─ Jsr4Z8.UI/         Avalonia UI
├─ tests/Jsr4Z8.Tests/   xUnit
├─ build.bat             一键构建（见 §6）
└─ out/                  分发产物
```

NuGet（锁定版本，同 Save_Z8）：Avalonia 11.2.2、Avalonia.Desktop 11.2.2、Semi.Avalonia 11.2.1.10、Avalonia.Fonts.Inter 11.2.2、CommunityToolkit.Mvvm 8.3.2。

## 5. GUI 定稿（中文界面 · Semi.Avalonia · 跟随系统深浅色+顶栏切换，默认暗色）

**主界面 = 极简卡片流**（mockup：`layout.html`）：顶栏 `JSR for Z8`（附「Nikon Z8 专用」标签）+ `＋ 添加任务组` + `▶ 全部开始`（存在就绪卡时可用）+ `⚙` + 主题切换；下方任务卡片纵列；空状态显示投放提示。

**新建任务组面板**（mockup：`add-task-flow-v3.html`）：单一虚线投放区（7 帧 RAW，文件名升序，第 1 张 = ★基准；芯片展示，点芯片换基准，× 移除，可继续拖入补齐/替换）+ 一条「选择黑场文件…」按钮（选中后显示文件名+机型/ISO/快门，可更换）；实时校验行（一致性 + PTC 匹配 + 满阱值）；「创建任务组」通过校验前禁用。

**卡片六态**（mockup：`card-states.html`）：就绪 / 运行中（阶段文字+进度条+■停止）/ 完成（输出路径+大小+耗时+📂打开文件夹）/ 校验失败（红芯片+错误条，无开始钮）/ 机型不支持 / 运行失败（人话错误摘要+↻重试）。日志默认收起，点「▾ 日志」手动展开。

**高级设置**（mockup：`settings.html`，B 版）：显存预算滑块 1–16GB（默认 4，可输数值）；输出路径单选「同输入目录/自定义+浏览」；临时路径单选「系统默认 %TEMP%/自定义」；底部实时「示例输出」预览；全局生效、持久保存。

## 6. 构建与分发（Windows Host 执行）

`build.bat`（从 WSL 经 interop 调用 `cmd.exe /c`）：

1. `git submodule update --init`；
2. 编译 LibRaw fork → `libs\libraw.dll` + wrapper；
3. 编译 libjpeg-turbo → `libs\jpeg62.dll`（或静态链接进 wrapper，按 Save_Z8 模式）；
4. 从 `reference/` 打包后端载荷 → 压缩资源（构建期生成 SHA256 清单）；
5. `dotnet publish -c Release`，self-contained 单文件，内嵌原生库与后端载荷；
6. 产物 `out\Jsr4Z8_v<版本>.exe`（预计 130–160MB）。

分发即此一个文件，面向任意用户下载；目标机需 Windows x64 + Vulkan 显卡（无需 .NET/Python）。**不做代码签名，不做 MSI/zip 改动**；README 提供 SmartScreen「更多信息→仍要运行」与杀软误报的说明。

## 7. 验证计划

- **xUnit**：PTC（表内 ISO 精确、表外拟合、499/500 边界、与原版插值对照）、8 文件校验规则、请求 JSON 构造、输出文件名生成、载荷清单校验。
- **端到端（Windows Host）**：`samples` 七帧+黑场完整跑通；检查产物 DNG：LibRaw 回读像素一致、Compression=7、EXIF/OpcodeList2/3/预览齐全、结构对照 Save_Z8 输出、体积明显小于未压缩。
- **打包产物冒烟**：干净目录运行（含中文路径样例副本），首次释放、二次启动跳过释放。
- 后端 stdout 协议（成功回执格式、进度行格式）在首次真实运行时实测补录到代码常量。
